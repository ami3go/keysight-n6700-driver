# v0.9.0 — 2026-10-29

## Scope

Feature and fix release on top of v0.8.0: the N679xA post-capture SENSe restore, supervised
source runs, the source ARB golden-vector and capability coverage, and two guarded HIL runners.

## Changes

- Fix the N679xA digitizer SENSe leak (PR #40). `configure_digitize()` overwrote
  `SENS:FUNC:VOLT/CURR`, `SENS:SWE:TINT/POIN/OFFS:POIN` but saved only `FORM`, so every later
  `MEASure` on the load integrated the whole capture: 515 ms instead of 27 ms after a
  48830 x 10.24 us capture on an N6791A. The pre-capture state is now restored with readback on
  `abort_digitize()`; fetch keeps the capture for re-fetch/re-arm. A failed restore is reported by
  `measurement_restore_status` and never fails a verified abort.
- Add `ElectronicLoadChannel.restore_measurement_defaults()` and
  `N6700.restore_load_measurement_defaults(channel)` for instruments left polluted by earlier
  releases, plus the non-energizing `scripts/measure_digitize_sense_leak.py`.
- Add supervised source runs (ARB-R04): `supervise_voltage_transient()` with a mandatory maximum
  runtime and verified OFF on deadline, abort, protection fault or drop-out.
- Add 27 golden SCPI vectors and the vendor-derived protocol/readback matrices (ARB-R05) and the
  ARB-R02 capability matrix (535 tests). No driver code change for these.
- Add the guarded source Arb HIL runner and evidence contract (ARB-R06) and the guarded
  buck-converter HIL; scoped "fully tested" claim for the N6775A + N6791A path only.
- Increment the distribution to 0.9.0 (display/archive 26.27); refresh generated artifacts.

## Explicit limits

- The SENSe restore runs on `abort_digitize()` only. Callers that fetch and never abort keep the
  capture sweep (documented). `configure_digitize_trigger()` still leaves `TRIG:ACQ` settings.
- Overall LPDS-001 §9 status stays `untested`; the scoped claim covers one N6700C with an N6775A
  and an N6791A.
- The `restore_load_measurement_defaults` conformance exclusion is pending independent review.
