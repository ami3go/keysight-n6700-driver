# v0.6.0 — 2026-10-09

## Objective

Give the N679xA electronic-load module a way to capture a real buffered
waveform of its own measured voltage/current, triggered on a level
crossing — a scope-less fallback for HIL tests downstream (in
`power_supply_test`) that currently need an oscilloscope to resolve
sub-50ms transients (startup/shutdown rise/fall time, load-transient
recovery time) and have none available on some benches.

## Source baseline

Builds on v0.5.0 (`keysight-n6700-driver`), no repository restructure.

## What the manual showed

The Keysight N6705C User's Guide / Programmer's Reference (bundled in
`Keysight_documents/N6791A_manual.pdf.md`), "Digitizing Measurements"
chapter and the "N679xA Load Model Differences" table: N6791A/N6792A
support buffered, triggered acquisition over the remote interface only
("SCPI command array readback", "SCPI command programmable sample rate",
"SCPI command external data logging" all marked available) — which is
exactly how an N6700 mainframe talks to it, since it has no front panel.
Sample interval is a minimum of 10.24 µs for 1-2 parameters ("all models",
not just the N678xA SMU family, which gets 5.12 µs single-parameter), with
a buffer depth up to 512K points, pre/post-trigger offset
(`SENS:SWEep:OFFSet:POINts`), and trigger sources including a
voltage/current level crossing on any channel — functionally the same edge
trigger a scope would use.

None of this existed in the driver before this release: no `SENS:SWEep`,
`TRIGger:ACQuire`, or array-fetch command anywhere in `driver.py`/
`channel.py`/`scpi.py`, and `module_capabilities.py`'s
`supports_array_measurement` flag wasn't even set for the N679 load family
despite the manual confirming hardware support.

## Added

- `ElectronicLoadChannel.configure_digitize`/`configure_digitize_trigger`/
  `arm_digitize`/`wait_digitize_armed`/`trigger_digitize`/
  `wait_digitize_complete`/`abort_digitize`/`fetch_digitized_array`,
  issuing `SENS:FUNC`/`SENS:SWEep:TINTerval`/`:POINts`/`:OFFSet:POINts`,
  `TRIGger:ACQuire:SOURce`/`:VOLTage`/`:CURRent`/`:SLOPe`, `INITiate:ACQuire`,
  `TRIGger:ACQuire`, `ABORt:ACQuire`, and `FETCh:ARRay:VOLTage?`/`:CURRent?`.
  `wait_digitize_armed`/`wait_digitize_complete` poll the operation-status
  register's `WTG_meas`/`MEAS_active` bits via the existing
  `STAT:OPER:COND?` query, reusing `scpi_driver_core`'s `poll_until` the
  same way `wait_for_voltage_in_range` already does.
- Matching thin `N6700` convenience wrappers of the same names;
  `configure_digitize` and `fetch_digitized_array` are `@capability`-
  decorated under the (previously unused) `acquisition`/`waveform`
  categories.
- `ChannelCapabilities.supports_digitizing`/`digitize_min_interval_s`, set
  only for `LOAD_PREFIXES` (`N679xA`) — the manual says the SMU/power-supply
  families support this too, but they are not classified for it yet; see
  `review/known_risks.md`. First bool+numeric-limit pairing in this
  dataclass.
- `types.ArrayMeasurement.interval_s` and `offset_points` — the dataclass already existed,
  exported, completely unused by any method before this release; completed
  its evident original intent rather than adding a new type.
- `tests/hardware/test_hardware_load_digitize.py`: a guarded real-hardware
  smoke test, executed successfully on the release bench.

## Design notes

Like `set_load_current_limit`, digitizing is real-hardware-only:
`SIM_LOAD` raises `DriverUnsupportedOperationError` rather than gaining a
parallel `SIM:LOAD:*` namespace, since there's no meaningful simulated-
waveform twin to build. Unit tests instead build an `ElectronicLoadChannel`
with real (`classify_module("N6791A")`) capabilities pointed at the
simulator's shared channel-3 command surface, the same pattern
`test_electronic_load_channel.py` already uses for the other real-load
commands. The simulator's new handling for this command surface is
deliberately flat — it accepts the configuration and, on fetch, replays the
channel's current scalar value `points` times — enough to exercise the
driver's configure/arm/poll/fetch sequence without pretending to model a
real transient waveform.

The conformance fixture's default simulated channel map classifies channel
3 as `SIM_LOAD` (see the comment atop `protocol_vectors.yaml`), which this
feature refuses by design, so none of the 8 new methods could reach their
real-command branch via a standard protocol vector. They are listed in
`exclusions.yaml` instead, same as the precedent set for
`get_remote_state`/`set_remote_state`/`remote_lockout`.

## Public API impact

Purely additive: 8 new methods on `ElectronicLoadChannel` and matching
`N6700` wrappers, 2 new `ChannelCapabilities` fields (default `False`/
`None`, so existing `classify_module()` callers see no change for any
other module family), 1 new field on `ArrayMeasurement` (defaulted, so
existing construction sites are unaffected — there were none in this
codebase before this release).

## Test/evidence summary

The full offline suite passes, including the new digitize validation in
`tests/unit/test_electronic_load_digitize.py` and assertions in
`test_module_capabilities.py`. `ruff` is clean. The 8 new
methods are conformance-excluded, not vectored — see Design notes.
`ai/ai_contract.yaml`, `capability/capability_model.yaml`, and
`tests/conformance/data/method_inventory.yaml` regenerated and committed in
sync with the live `@capability` annotations.

## What was run

Against the real N6700C at 192.168.0.6, channel 2 (N6791A):
`tests/hardware/test_hardware_load_digitize.py` passed —
`configure_digitize`/`arm_digitize`/`wait_digitize_armed`/
`trigger_digitize`/`wait_digitize_complete`/`fetch_digitized_array`
round-tripped a real 256-point buffer at a 20.48 µs sample interval in
0.24s. Both the source (channel 1) output and load (channel 2) input were
independently confirmed off afterward, with an empty error queue.

The guarded pytest is a software (`BUS`)-triggered round trip. It was
followed by the full downstream DUT transient matrix using the N6791A's
own current-level trigger: 8/13.5/18 V, both 0.5→2.5 A and 2.5→0.5 A,
1024 points at 20.48 µs/sample, and 512 pre-trigger points. All six edges
landed at sample 511–512. Worst VOUT deviation was 3.357% (110.55 mV),
recovery into the 2% band was 20.48–40.96 µs, no protection flags became
active, and final verification found both channels off with an empty error
queue. Raw evidence and the exact harness are retained under
`results/load_transient/20261009_n6791a_internal_buffer/`.

## Known limitations

Current-level triggering and pre-trigger capture are now exercised against
a real DUT. Voltage/external/transient trigger sources and other module
families remain unqualified. SMU (`N678xA`) and power-supply (`N676xA`)
families are not yet classified
`supports_digitizing`, even though the manual says they support the same
subsystem — extending to them is additive follow-up, not planned here.
