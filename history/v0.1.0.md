# v0.1.0 — 2026-09-13

## Objective

First release of `keysight-n6700-driver`: port the Robot-Framework-first
`rf_keysight_n6700` driver (in `ami3go/RobotFrameworks_hw_drivers`) into its
own repository as a Python-first driver with an optional Robot Framework
adapter, per the Lab pyDrivers Standard (LPDS), and rebuild its transport/SCPI
layer on `scpi-driver-core` instead of a hand-rolled implementation.

## Source baseline

Ported from `rf_keysight_n6700` at
`ami3go/RobotFrameworks_hw_drivers@9a8e59a` (v26.9.0 of that driver). The
underlying SCPI command semantics (channel-list syntax, module
classification, measurement fallback logic, protection-status bit masks) are
carried over unchanged; the transport, SCPI-client, exception hierarchy,
session/state model, and package layout are new.

## Added

- `src/keysight_n6700/base.py` — a local LPDS-003 `BaseInstrument`
  foundation (9-state machine, session registry, `_execute_operation`,
  exception translation, diagnostics export), built on `scpi-driver-core`.
- `src/keysight_n6700/capability_model.py` — LPDS-013 capability discovery
  (`@capability` decorator + the six mandatory discovery methods).
- `src/keysight_n6700/configuration.py` — LPDS-014 configuration model
  (JSON Schema + the eight mandatory configuration methods).
- `src/keysight_n6700/plugin.py`, `.../resources/plugin_manifest.json` —
  LPDS-015 driver-side plugin provider and manifest.
- `adapters/robotframework/` — the Robot Framework adapter as its own
  subpackage with its own plugin/manifest, versioned independently.
- `ai/ai_contract.yaml` / `.lock` — LPDS-017 AI-facing contract, generated
  from the capability model plus hand-authored mental model/safety/state
  content.
- `tests/conformance/` — LPDS-019 call/protocol conformance suite: 25
  realized protocol vectors plus a reviewed exclusion list for the rest.
- `capability/capability_model.yaml` / `.schema.json` — the packaged LPDS-013
  artifacts, generated from the same annotations as the discovery API.
- LPDS-002 canonical public API (`connect`, `get_identity`, `set_dc_voltage`,
  `enable_output`, `measure_dc_voltage`, `safe_shutdown`, ...) alongside the
  richer typed accessors (`power_supply()`, `smu()`, `load()`) the original
  driver already had.
- Multi-session support: one `N6700()` instance can now hold several named
  sessions (`alias=`) at once; the Robot Framework adapter now holds one
  driver instance instead of one per alias.

## Changed

- `keysight_n6700/exceptions.py` — replaced with the LPDS-007 `DriverError`
  hierarchy. The old `N6700ConnectionError`/`N6700CommandError`/etc. names no
  longer exist; see `src/keysight_n6700/_translate.py` for the mapping from
  the previous exception vocabulary's intent.
- `keysight_n6700/transport.py` and the hand-rolled `Transport` protocol were
  removed; `VisaTransport`/`TcpTransport` from `scpi-driver-core` are used
  directly, and the simulator was rebuilt on
  `scpi_driver_core.simulation.scripted.ScriptedScpiTransport`.
- Package layout moved to `src/` (LPDS-005 §6.1), and the Robot Framework
  library moved from a top-level `KeysightN6700Library/` into
  `adapters/robotframework/keysight_n6700_robotframework_adapter/`.

## Compatibility

Breaking, relative to `rf_keysight_n6700`: import paths, exception classes,
and the Robot Framework library's import path all changed. This is a new
repository, not a drop-in upgrade; see `docs/architecture.md`.

## Test/evidence summary

190 tests pass (46 unit, 129 conformance, 4 capability-model, an adapter
translation suite) against the simulator; `ruff` and `mypy --strict` (driver
package) are clean. No real-hardware run has been performed — see
`review/known_risks.md`.
