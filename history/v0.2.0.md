# v0.2.0 — 2026-09-13

## Objective

Integrate the `scpi-driver-core` capabilities that v0.1.0 depended on but
did not use beyond the transport/session layer: protocol tracing, bounded
wait-for-condition polling, retry for idempotent queries, and a confirmation
guard for raw SCPI.

## Source baseline

Builds on v0.1.0 (`keysight-n6700-driver@6ccaf89`), no repository restructure.

## Added

- `connect(protocol_trace=..., protocol_trace_redactor=...)` — real
  transport-boundary protocol tracing (LPDS-008), via
  `scpi_driver_core.tracing.instrumented.InstrumentedTransport` and
  `Tracer`. Accepts a path (wrapped in `JsonlTraceSink`, closed automatically
  on disconnect) or any `TraceObserver` (e.g. `RecordingTraceObserver` for
  tests). `base.py` gained two new hooks, `_get_tracer(alias)` and
  `_on_disconnected(alias)`, and `_build_transport` now receives `alias`.
- `N6700.wait_for_voltage_in_range` / `wait_for_current_in_range` — bounded
  polling on `scpi_driver_core.execution.polling.poll_until`, raising
  `DriverTimeoutError` on deadline. The Robot Framework adapter's `Wait
  Until N6700 Voltage Is In Range` keyword now delegates to the driver
  method instead of its own hand-rolled loop.
- `query_scpi(..., retry_attempts=, retry_delay_s=)` — optional retry for a
  caller-asserted-idempotent raw query, via
  `scpi_driver_core.execution.retry.RetryPolicy`/`ReplayPolicy.SAFE`.
- `set_raw_scpi_guard` / `enable_raw_scpi` / `disable_raw_scpi` — an opt-in
  `scpi_driver_core.execution.guards.ConfirmationGuard` in front of
  `write_scpi`/`query_scpi`. New capability `safety.raw_scpi.guard`.
  New Robot Framework keywords `Set/Enable/Disable N6700 Raw SCPI Guard`.
- `_translate.py`: `SafetyGuardError` (core) now maps to
  `DriverUnsafeOperationError`, code `LPDS-SAF-001`.
- `tests/unit/test_scpi_driver_core_integration.py` (12 tests) and 3 new
  adapter translation tests cover all of the above against the simulator.

## Changed

- `capability/capability_model.yaml`, `ai/ai_contract.yaml`,
  `tests/conformance/data/method_inventory.yaml`/`exclusions.yaml`
  regenerated: 20 capabilities (was 17), 105 inventoried methods (was 100),
  74 device-facing (was 72; +2 for the new wait-for-range methods, +0 net
  for the 3 new guard-configuration methods which are local bookkeeping, not
  device-facing).

## Public API impact

Purely additive. No existing method's signature or default behavior
changed; `write_scpi`/`query_scpi` are unguarded by default exactly as
before unless `set_raw_scpi_guard` is called explicitly.

## Test/evidence summary

214 tests pass (up from 189) against the simulator; `ruff` and
`mypy --strict` clean on both packages.

## Known limitations

Unchanged from v0.1.0 — see [`review/known_risks.md`](../review/known_risks.md).
The LPDS-008 gap noted there is now narrower: transport-boundary tracing is
real; the full results-directory evidence tree is still a harness's job,
not the driver's.
