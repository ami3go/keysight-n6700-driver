# v0.7.9 — 2026-10-15

## Scope

DRV-ARB-A: mainframe/Option 054 capability safety gate only. The remaining
DRV-ARB-B through DRV-ARB-I work packages are **not** implemented by this PR.

## Changes

- Explicit vendor-reviewed supported module identifiers rather than prefix-only
  advertising of source LIST/Arb functionality.
- N6700C requires Option 054 for N6731B–N6736B, N6741B–N6746B,
  N6751A–N6756A and N6773A–N6777A. N6761A–N6766A precision
  models and N678xA SMUs follow their distinct vendor capability tables.
- N6705C uses its separately documented built-in Arb capability context.
- Unknown chassis, firmware, model or options disable source LIST and Arb.
  This is conservative: unsupported/unqualified identities cannot be
  overridden by a successful raw SCPI probe.
- Discovery context includes normalized immutable metadata and stable
  SHA-256 fingerprints. Rediscovery and disconnect revoke old channel
  handles and invalidate old transient configuration/generation tokens.
- LIST now checks the advertised capability **before the first SCPI write**.
- Simulated mainframe identifies as N6705C, preserving its existing
  software LIST/UDEF regression coverage without falsely endorsing N6700B.
- Version 0.7.9, distribution metadata and AI-contract SHA-256 lock refreshed.
- Workflow and per-test execution watchdogs to bound CI hangs.

## Evidence and acceptance

- Module and mainframe matrix tests (including rejected Option 054 and
  unknown firmware/option/model) in tests/unit/test_arb_capability_gates.py.
- Regressions for simulator capability, reject-before-write and stale
  channel reuse.
- Existing LIST/UDEF/SMU/load regression suite must pass on Python 3.10
  and Python 3.13 with Ruff, mypy, structure and generated-contract checks.
- Physical analog waveform accuracy and DSO acceptance **not tested**;
  do not use a passing simulator as hardware qualification.
